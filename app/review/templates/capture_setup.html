{% if tab == 'gmail' %}

Gmail

Open a booking email, press one button, and it is captured. You build a small Google Apps Script add-on once, in your own Google account. It only reads the email you have open and never moves or labels it.

  1. Go to script.google.com and choose New project. Name it "Run·dere Capture".
  2. Open Project Settings (the gear) and tick Show "appsscript.json" manifest file in editor. Back in the editor, open appsscript.json and replace everything in it with: {% if gmail_manifest %}{{ copyblock('gmail-manifest', gmail_manifest) }}{% else %}
    the file capture/gmail-addon/appsscript.json.{% endif %}
  3. Open Code.gs and replace everything in it with: {% if gmail_code %}{{ copyblock('gmail-code', gmail_code) }}{% else %}
    the file capture/gmail-addon/Code.gs.{% endif %}
  4. Make your own key. It is yours alone, so what the add-on sends lands in your queue. {{ keystep('gmail') }}
  5. Choose Deploy → Test deployments → Install add-on. This installs it for your Google account only. The first time, Google says "this app isn't verified": choose Advanced, then Go to … (unsafe). It is your own script, so this is expected.
  6. Open Gmail and refresh. Open any email, then the Run·dere icon in the side panel. On the home card paste your key and the Ingest URL{% if ingest_is_public %} ({{ ingest_url }}){% endif %}, then Save.
  7. Check it works: open an email, press Capture to Run·dere. A message says Captured. batch_id=…. The email then shows in your Inbox after it has been read.
If it doesn't work
  • 401 bad signature: the key was pasted with a space or from an older key. Make a new key and paste it again.
  • "Expired access token": re-copy Code.gs; older copies kept a stale token.
  • Still asks for Gmail "modify" access: you installed an older copy. Re-copy both files, then Deploy → Test deployments, remove the install and install it again.
  • The full guide is capture/gmail-addon/README.md in the repository.
{% elif tab == 'calendar' %}

Calendar

Open a calendar event, press one button, and it is captured. Same idea as Gmail, with its own small add-on.

  1. Go to script.google.com and choose New project. Name it "Run·dere Calendar".
  2. Open Project Settings and tick Show "appsscript.json" manifest file in editor. Replace the contents of appsscript.json with: {% if gcal_manifest %}{{ copyblock('gcal-manifest', gcal_manifest) }}{% else %}
    the file capture/gcal-addon/appsscript.json.{% endif %} It turns on the Calendar service the script needs.
  3. Replace the contents of Code.gs with: {% if gcal_code %}{{ copyblock('gcal-code', gcal_code) }}{% else %}
    the file capture/gcal-addon/Code.gs.{% endif %}
  4. Make your own key. {{ keystep('calendar') }}
  5. Deploy → Test deployments → Install add-on, and get past the "this app isn't verified" screen (Advanced → Go to … (unsafe)).
  6. Open Google Calendar and refresh. Open an event, then the Run·dere icon in the side panel. Paste your key and the Ingest URL{% if ingest_is_public %} ({{ ingest_url }}){% endif %} on the home card and Save.
  7. Check it works: open an event and press Capture to Run·dere. You should see Captured.
If it doesn't work
  • "does not have permission … calendar.addons.execute": re-copy appsscript.json, save, reload Calendar.
  • "Calendar is not defined": the manifest's Calendar service entry is missing. Re-copy it and reinstall.
  • The full guide is capture/gcal-addon/README.md.
{% elif tab == 'bookmarklet' %}

Bookmarklet

A bookmark that captures whatever page you are looking at, even one behind a login. Best on a computer; phones use the app instead.

  1. Show your browser's bookmarks bar (Chrome, Edge, Firefox: Ctrl/⌘ + Shift + B).
  2. Drag this button onto the bar:

    Capture to Run·dere

  3. Open a booking confirmation page and click the bookmark. A Run·dere tab opens, you may be asked to sign in, and it names the site the page came from: click Capture it and the page is captured and read.
  4. Check it works: that tab ends with a card for what was found, with Open in Inbox.
If it doesn't work
  • Nothing opens: your browser blocked the pop-up. Allow pop-ups for the booking site, then click again.
  • Pop-ups are not allowed: the page's HTML is copied to your clipboard instead. Paste it into the box on Capture.

AI assistants (MCP)

Run·dere has a standard remote MCP (Model Context Protocol) server. Any assistant or tool that speaks MCP can connect to it, then capture a link for you when you ask. It acts as you: it only sees and changes what you can in Run·dere.

  1. In your assistant or MCP client, add a remote MCP server (some call it a custom connector) with this URL: {{ copyblock('mcp-url', mcp_url) }} Leave any client id or secret empty: the assistant registers itself.
  2. Connect. Run·dere opens its own sign-in page, then asks Allow access to your Run·dere data? Choose Allow.
  3. Check it works: ask the assistant "Capture this page for me: https://…". It uses the capture_url tool, and the item appears in your Inbox.
Examples and other ways to connect
  • Claude (claude.ai, Desktop, mobile): Settings → Connectors → Add custom connector, name it Run·dere, paste the URL.
  • Claude Code: claude mcp add --transport http rundere {{ mcp_url }}, then /mcp to sign in.
  • A client without browser sign-in: make a personal API token under Account and send it as Authorization: Bearer ….
  • The server needs to be reachable from the assistant (a hosted assistant connects from its own cloud). Admin details are in docs/claude-connector.md.
